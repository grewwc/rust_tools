# Deep audit child rules

Apply these additional rules only for `/audit --deep`. Keep the existing `<audit_report>` shape and protocol limits unchanged; no inventory or finding-key field is added.

- **Default to read-only**: do not modify reviewed source unless the user explicitly asks for fixes or report-file updates. Audit confidence never expands existing authorization; for fixes beyond it, supply evidence, options, impact, reversibility, and estimated cost for the user's fix / narrow / accept / rollback decision.
- **Budget the audit to fit its deadline**: the runtime sends a wrap-up signal before the hard timeout — when it arrives, stop expanding immediately and synthesize from the evidence and `AUDIT_CHECKPOINT:` records already gathered. Work high-risk paths first — control flow, error handling, resource lifetimes, permissions, security-sensitive surface, and the exact change the user asked about — then broaden only if time remains. Start writing the final report early enough to finish within the deadline. A clean review with an explicit coverage-gap list is a complete bounded report, not proof of task acceptance. Anything you cannot verify in time belongs in `open_questions` / `coverage_gaps`, not in `findings`.
- **Respect the lead's inventory and round**: start from the supplied R0 checklist and read list; verify coverage with your own reads, and keep unknown ownership as a `coverage_gap`. Stay on the assigned invariant/consumer boundary, not a file-only partition. Parallel children on one snapshot form one round; the lead owns inventory/disposition tables and the two-round limit. For a second-round task, check its named T1 gap/question, T2 behavior/contract mutation, or T3 mechanical high-impact predicate (persistence/schema/shared-contract/auth/security/concurrency) with no round-one P0/P1; require a changed scope/diff/consumer, falsification task, or tier rather than repeating the same prompt. Re-read citations after line drift; record comment/doc-only edits without re-audit when behavior/contracts are unchanged. Report unclosed items in the existing lists.
- **Bound the expansion by the caller's scope and the wrap-up signal**: inspect the named high-risk ranges until they are verified; when the wrap-up signal arrives, stop expanding and synthesize. If the scope cannot be covered in that window, name the unread ranges in `coverage_gaps`; the caller may use one narrow follow-up per recorded trigger within the two-round limit, then reports unresolved items. Baseline reconstruction and consumer searches for the changed symbols count as in-scope, not expansion. Report every verified finding; the report protocol's limits are the only output cap.
- **Fast mode: Default to read-only**: do not modify reviewed source unless the user explicitly asks for fixes or report-file updates. Audit confidence never expands existing authorization; for fixes beyond it, supply evidence, options, impact, reversibility, and estimated cost for the user's fix / narrow / accept / rollback decision.
- **Fast mode: Respect the lead's inventory and round**: start from the supplied R0 checklist and read list; verify coverage with your own reads, and keep unknown ownership as a `coverage_gap`. Stay on the assigned invariant/consumer boundary, not a file-only partition. Parallel children on one snapshot form one round; the lead owns inventory/disposition tables and the two-round limit. Re-read citations after line drift; record comment/doc-only edits without re-audit when behavior/contracts are unchanged. Report unclosed items in the existing lists; escalate mandatory full-audit scope to `audit`.
- **Fast mode: Bound the review by the caller's scope and the wrap-up signal**: inspect the named high-risk ranges until they are verified; when the wrap-up signal arrives, stop expanding and synthesize from the evidence already collected. If the scope cannot be covered in that window, list the unread ranges in `coverage_gaps` and recommend a full `audit` or a separately scoped audit only within the lead's two-round limit and one narrow follow-up per recorded trigger; otherwise report unresolved items. Never imply coverage you did not verify. Report every verified finding; the report protocol's limits are the only output cap. Write the report once, in the final turn.
- **Fast mode: Wrap up early**: record a short `AUDIT_CHECKPOINT:` line after each checked branch so partial evidence survives a timeout; once the highest-risk paths are verified and no further high-value check remains, stop expanding and produce the final conclusion. A bounded review with a clear coverage-gap list is a complete bounded report, not proof of task acceptance; leaving unread high-risk ranges silently is not.
